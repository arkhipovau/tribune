# Tribune: 3D-стадион

Здесь лежит 3D-стадион для сайта Tribune (Babylon.js + Vite + TypeScript).

## Куда заливать правки

Работай в ветке **`3d-stadium`**. Заливай туда когда угодно.

- В `main` не заливай: эта ветка — живой сайт https://arkhipovau.github.io/tribune/.
- На сайт стадион попадает, когда Julie решает его обновить. Тогда правки из `3d-stadium` забирают, проверяют в браузере и переносят в `main`.

```bash
git clone https://github.com/arkhipovau/tribune.git
cd tribune
git checkout 3d-stadium
cd stadium-src
npm install
npm run dev
```

Тестовая страница: http://localhost:5173. Чтобы посмотреть стадион так, как он выглядит на сайте (только модель и кнопки сайта), открой http://localhost:5173/?embed. Диагностика: `?diagnostics=1`.

## Важно про `src/stadium.ts`

Это твой `main.ts` из MVP от 13.11.2026. Сцена, материалы, свет, камера и адаптивное разрешение в нём без изменений. Чтобы стадион работал внутри сайта, к нему добавлено встраивание. Правь сцену прямо в этом файле, тогда переносить правки вручную не придётся.

Что добавлено и что не нужно ломать:

1. **Функция `mountStadium(root, options)`.** Весь код сцены находится внутри неё. Сцена встраивается в переданный элемент, а не в `<body>`, и не трогает стили `html` и `body`: на сайте это карточка внутри страницы, вокруг которой страница прокручивается.
2. **Пути к ассетам приходят из `options`:** `modelsUrl`, `envUrl`. Сайт лежит в подпапке `/tribune/`, абсолютный путь `/models/` там не работает.
3. **Встраиваемый режим `panels: false`.** Боковой список команд скрыт. Кнопки Back to stadium и Open club page собраны в одну капсулу в стиле сайта внизу по центру. Надпись TRIBUNE и кнопка «← К СТАДИОНУ» на сайте не используются.
4. **Рендер идёт, только пока стадион виден на экране** (IntersectionObserver).
5. **Импорты Babylon точечные** (`@babylonjs/core/...`), а не из `@babylonjs/core` целиком. Иначе сборка весит около 7 МБ вместо 2,5 МБ. Если нужен новый класс, импортируй его из его файла.
6. **В `AtmospherePlugin.getUniforms()` есть блок `fragment`** с объявлениями всех uniform `tribune*`. Без него в части браузеров шейдер не компилируется («undeclared identifier»), и стадион не рисуется, остаётся одно поле. Это воспроизводится и в исходной сборке MVP. Если добавляешь новый uniform в плагин, добавь его и в `ubo`, и в `fragment`.

## Модели

Модели кладутся в `public/models/` как есть. Имена файлов должны совпадать с теми, что указаны в `SETTINGS` и `TEAMS` в `src/stadium.ts`.

## Проверка перед заливкой

```bash
npx tsc --noEmit
```

В тестовой странице не должно быть ошибок в консоли. Стадион и все дома должны рисоваться, в том числе в режиме `?embed`.
